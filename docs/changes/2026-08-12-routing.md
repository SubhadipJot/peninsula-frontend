# React Router + Production-Ready Structure

**Date:** 2026-08-12

## Summary

Added client-side routing (React Router v7) and reorganized the frontend into a production-ready structure with route-based code splitting.

## Changes

- Installed `react-router-dom` (v7).
- New structure:
  - `src/router/index.tsx` — `createBrowserRouter` with route-level `lazy()` loading (RRv7 idiomatic; each page splits into its own chunk).
  - `src/layouts/root-layout.tsx` — sticky header with nav (Home / Jobs / Applications), `<Outlet />` in `<Suspense>`, footer.
  - `src/pages/home/` — HomePage (previous welcome screen).
  - `src/pages/jobs/` — JobsPage (placeholder).
  - `src/pages/applications/` — ApplicationsPage (placeholder).
  - `src/pages/not-found/` — NotFoundPage (404).
  - `src/config/env.ts` — typed env access (`VITE_API_URL`, `NODE_ENV`).
- `main.tsx` now renders `<RouterProvider router={router} />`; removed `App.tsx` (obsolete).
- Added `.env.example` with `VITE_API_URL`.
- Replaced `asChild` with Base UI's `render` prop (`<Button render={<Link to="/" />} />`) — the shadcn Base UI button doesn't support `asChild`.

## Verification

- `pnpm exec tsc --noEmit -p tsconfig.app.json` passes.
- `pnpm lint` reports only the known shadcn `buttonVariants` warning.
- `pnpm build` succeeds; output shows per-page chunks (home-page, jobs-page, applications-page, not-found-page).
- Preview server returns 200 for `/`, `/jobs`, and unknown paths (SPA fallback).
